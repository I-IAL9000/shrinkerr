# v0.9.0 Image-Subtitle OCR Language Detection Design Spec

**Version target:** v0.9.0 (the image-sub half of the language-detection line; deferred from v0.8.0)
**Status:** Design — awaiting implementation plan
**Decisions locked via Q&A:** full multi-script (Latin + CJK + Cyrillic + Arabic); on-demand only (not scan, not pre-conversion); PGS + VobSub formats; tesseract + packs baked into all images (no separate variant); built subagent-driven on a feature branch with NUC-verification checkpoints.

---

## Background

v0.8.0–0.8.3 built language detection for `und` **text** subtitles (langdetect,
incl. charset detection for legacy CJK encodings) and **audio** (faster-whisper),
plus writing detected tags back to the file (`apply_track_languages_to_file`).
**Image-based subtitles** — PGS (`hdmv_pgs_subtitle`, Blu-ray) and VobSub
(`dvd_subtitle`, DVD) — were explicitly deferred: they're bitmaps, so detecting
their language needs OCR.

v0.9.0 adds that OCR front-end. The key architectural fact: v0.8.0's apply layer
is **codec-agnostic** — it keys on the detection *result*, not the track codec.
So OCR is purely additive: it produces text, and the existing
`detect_subtitle_language` → confidence-gate → persist → `apply_track_languages_to_file`
path handles everything downstream unchanged.

## Reality check (read before planning)

OCR of bitmap subtitles is finicky and **cannot be validated in the dev sandbox**
(no tesseract, no PGS/VobSub sample files, no OCR tooling). Like the v0.6.x/0.7.x
disc-metadata line, this will need **RC-style iteration on the user's NUC** with
real files. The plan MUST be structured around that: build the pipeline with
mocked OCR in unit tests, then verify+iterate on the NUC between phases. The exact
extraction/render tooling (see below) is a plan-phase decision to be confirmed on
the first real run, not asserted up front.

## Approach

New module `backend/image_sub_ocr.py`. One public entry point:

```python
async def detect_image_sub_language(
    file_path: str, stream_index: int, codec: str
) -> tuple[str | None, float]:
    """OCR a sample of an und PGS/VobSub track and detect its language.
    Returns (ISO 639-2 B-form, confidence) or (None, 0.0). Fail-open."""
```

### Pipeline (per und image-sub track, on-demand)

1. **Extract a bounded sample** of subtitle bitmap cues (cap ~30–40, NOT the whole
   track — OCR is slow) as PNG images.
   - **PGS** (`hdmv_pgs_subtitle`): `mkvextract tracks <file> <n>:out.sup`
     (mkvtoolnix — already in the image from v0.8.3) → decode `.sup` bitmaps to
     PNGs.
   - **VobSub** (`dvd_subtitle`): extract the `.idx`/`.sub` pair → render cue
     bitmaps to PNGs.
2. **Script detection**: run tesseract OSD (`--psm 0`) over the sample → dominant
   script (Latin / Han / Japanese / Korean / Cyrillic / Arabic).
3. **OCR** the sample with the tesseract language pack matching the detected
   script (script→pack map below).
4. **Detect language**: concatenate the OCR'd text and pass it to the existing
   `backend.language_detection.detect_subtitle_language(text)` → confidence gate →
   ISO 639-2.

### Script → tesseract pack map

| OSD script | tesseract lang(s) to OCR with | langdetect resolves to |
|---|---|---|
| Latin | `eng` (reads all Latin languages) | actual Latin lang (eng/fre/ger/swe/…) |
| Han | `chi_sim+chi_tra` | chi |
| Japanese | `jpn` | jpn |
| Korean | `kor` | kor |
| Cyrillic | `rus` | rus (+ other Cyrillic via langdetect) |
| Arabic | `ara` | ara |

The OCR pack only needs to get the *script* right; langdetect identifies the
specific language from the recognized text (robust to OCR noise given sample
volume). This is why one Latin pack covers all Latin-script languages.

### Tooling (leading candidates — confirm on first NUC run)

- **PGS**: leading candidate `pgsrip` (pip; wraps mkvextract + tesseract). If it
  doesn't fit the sample+OSD flow (it OCRs whole tracks with a fixed language),
  fall back to manual: `mkvextract` → parse `.sup` (e.g. `pgsreader`) → PIL images
  → `pytesseract` (OSD + OCR). The plan's Phase 1 settles this against a real file.
- **VobSub**: extract `.idx`/`.sub`, render via a vobsub decoder → `pytesseract`.
- **OSD + OCR**: `pytesseract` (wraps the tesseract binary) is the common thread;
  `tesseract-ocr` + packs are apt deps.

The plan should keep the extraction tooling behind a small internal seam so the
PGS/VobSub extractor can be swapped without touching the OSD/OCR/detect logic.

## Wiring

The `/detect-languages` endpoint (`backend/routes/scan.py`) currently gates image
codecs out via `_TEXT_SUB_CODECS`. Add an **image-sub branch**: for an und track
whose codec is PGS/VobSub, call `detect_image_sub_language`. A detected language
flows into the SAME per-type-ordinal write lists (`audio_write`/`sub_write`) and
the SAME `apply_track_languages_to_file` call added in v0.8.3 — so the tag gets
written to the file (mkvpropedit) exactly like a text-sub detection.

On-demand only: NOT added to the scanner (would be brutal on a library) and NOT
to the pre-conversion hook (would add minutes per encode).

## Dependencies

Add to both Dockerfiles: `tesseract-ocr` + `tesseract-ocr-eng tesseract-ocr-chi-sim
tesseract-ocr-chi-tra tesseract-ocr-jpn tesseract-ocr-kor tesseract-ocr-rus
tesseract-ocr-ara` (tens of MB total). Add to `requirements.txt`: `pytesseract`,
and the chosen PGS/VobSub extraction lib (`pgsrip` and/or `pgsreader` + `Pillow`) —
finalized in Phase 1.

## Confidence & fail-open

- Same confidence gate as text subs (`SHRINKERR_LANG_DETECT_SUB_MIN`, default 0.7).
  OCR is noisy, so the gate is the safety net against a wrong-but-confident guess —
  leave the track `und` rather than mistag it.
- Every step is fail-open: extraction fails / no tesseract / OSD inconclusive /
  langdetect below threshold → return `(None, 0.0)`, log `[IMG-OCR]`, never raise,
  never block the endpoint.
- Bounded work: sample cap + per-step timeouts so a pathological track can't hang.

## Testing

- **Unit (sandbox):** script→pack mapping; the extraction command builders
  (mkvextract/tesseract argv shape); the OCR-text → `detect_subtitle_language`
  handoff (mock the OCR subprocess to return canned text, assert ISO 639-2 out);
  fail-open on subprocess error. No tesseract/PGS needed.
- **Integration (NUC):** real PGS + VobSub files. This is where extraction quality,
  OSD accuracy, and OCR output get validated and iterated. Expect multiple RC
  passes to tune (sample size, psm mode, pack selection).

## NUC verification checkpoints (between plan phases)

1. **Extraction spike** — confirm we can turn ONE real PGS track into PNG images
   (or OCR text) by the chosen tooling, in the actual image. Adjust tooling before
   building the module around it.
2. **End-to-end on a known file** — a PGS sub in a known language detects correctly
   and `mkvpropedit` writes the tag; verify with `mediainfo`.
3. **VobSub** — same on a DVD-sourced VobSub file.
4. **Non-Latin** — a Chinese/Japanese PGS sub resolves to chi/jpn.

## Acceptance criteria

1. On-demand "Detect languages" on a file with an und PGS sub OCRs a sample,
   detects the language (above threshold), persists it, and writes the tag to the
   file via mkvpropedit — verifiable with `mediainfo`.
2. VobSub (`dvd_subtitle`) works the same.
3. A non-Latin (e.g. Chinese) image sub resolves to the right ISO 639-2 code.
4. OCR failure at any step leaves the track `und`, logs `[IMG-OCR]`, and never
   breaks the endpoint or other (text/audio) detection in the same request.
5. Image-sub OCR does NOT run at scan or before conversion — on-demand only.
6. Unit tests (mapping + command builders + text handoff + fail-open) pass in CI
   without tesseract.

## Risks

- **OCR quality / can't test locally** — biggest risk. Mitigated by NUC checkpoints
  + the confidence gate (bad OCR → und, not wrong tag). Accept iteration.
- **Tooling fit** — pgsrip may not suit the sample+OSD flow; the manual
  mkvextract+pgsreader+pytesseract path is the fallback. Phase 1 spike decides.
- **Image size** — accepted by the user (packs add tens of MB to all variants).
- **VobSub rendering** — the fiddlier of the two pipelines; if it proves
  disproportionately hard, ship PGS-only and defer VobSub rather than block.

## Deferred / out of scope

- dvb_subtitle (broadcast) — rare, not worth a third pipeline.
- Full transcription / burning OCR'd subs to srt — we only need enough text for
  language ID, not a usable subtitle track.
- Bulk backfill of existing und image subs — on-demand per-file/batch covers it.
