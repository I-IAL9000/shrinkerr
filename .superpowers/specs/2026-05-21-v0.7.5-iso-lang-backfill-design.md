# v0.7.5 — BD ISO Language Metadata Backfill Design Spec

**Version target:** v0.7.5 (continuation of the v0.7.x ISO support line)
**Status:** Design — awaiting implementation plan
**Decisions locked via Q&A:** selector treats only `["und"]` and `[]` audio_tracks as stale; BD ISOs only; silent log-only signal

---

## Background

v0.7.4 added the libbluray ctypes fallback (`_parse_disc_languages_iso_via_libbluray`) that finally extracts language metadata from UDF-only BD ISOs — the discs that pycdlib and bsdtar/libarchive 3.7.2 both fail on. Layer-2 verification against Elephant (2003) confirmed the path returns `audio: [fre, eng], subtitle: [fre, fre]`.

However: existing scan_results rows for BD ISOs that were scanned under v0.7.0–v0.7.3 carry the **all-und** result from the previous fallback chain (pycdlib failed → bsdtar failed → empty). Those rows persist after the upgrade — the watcher's normal re-probe cycle isn't triggered just because the parser improved. Users would have to manually delete each affected row and let it re-discover.

The v0.6.5 release set the precedent for this exact pattern: when the disc IFO/mpls parsers were first added, existing rows that pre-dated the parsers were swept by a one-shot startup backfill (`_backfill_disc_languages_v065`). v0.7.5 follows the same shape, scoped to the discs v0.7.4 specifically fixed.

User impact today: if a user upgrades to v0.7.4 with existing BD ISO rows, those rows still display every track as `und`, every track gets dropped at convert-time under their `always_keep_languages` filter, and the conversion produces a tracks-stripped output (or fails the row-add check, depending on settings). User has to manually delete-and-rediscover each affected row — for a library with dozens of BD ISOs, that's a lot of clicks.

## Scope (locked via Q&A)

- **BD ISOs only.** DVD ISOs and folder discs are out of scope — their language metadata already worked under v0.7.0–v0.7.3, so backfilling them would be defensive sweep with no expected change.
- **"Stale" means strictly all-und or empty.** Rows with partial coverage (e.g. `[eng, und]`) are skipped — they reflect either a real disc that legitimately has an und track, or a v0.7.0 partial-extract that the user has already accepted. Out of scope for v0.7.5.
- **Silent log-only signal.** No UI toast, no scan-summary entry. Matches v0.6.5's pattern. Backfill is invisible to the user except for the log line.
- **One-shot.** Idempotent via `settings.iso_lang_backfilled_v075` flag. Set at sweep end regardless of per-row outcomes (so a single failing disc doesn't keep the sweep retrying forever).
- **Fail-open per row.** A row whose re-probe still returns all-und (because libbluray itself failed on that specific ISO) is skipped without error — it just stays in its current state. Not v0.7.5's problem to fight.

Explicitly NOT in scope:
- New parser logic (v0.7.4 shipped the parser; v0.7.5 just re-runs it on existing rows)
- Schema migrations
- UI changes
- DVD ISO or folder disc re-sweep
- Manual "backfill now" trigger from settings UI

## Design

### Trigger

New private async method on `DiscoveryWatcher` (the class that owns `_backfill_disc_languages_v065`):

```python
async def _backfill_iso_languages_v075(self) -> None: ...
```

Called from `check_once()` at startup, after the existing v0.6.5 and v0.6.7 backfills:

```python
async def check_once(self) -> dict:
    await self._backfill_disc_languages_v065()
    await self._backfill_estimated_savings_v067()
    await self._backfill_iso_languages_v075()   # <-- new
    # ... rest of check_once
```

The method is invoked on every watcher cycle but short-circuits after the first run via the settings flag — same cost shape as v0.6.5.

### Selector (two-stage)

**Stage 1 — SQL pull.** Cheap candidate filter, narrows the haystack to BD-ISO rows that *might* be stale. Shown here as the actual Python source-form string so the inner double-quotes are escape-correct for a copy-paste:

```python
async with db.execute(
    "SELECT file_path, audio_tracks_json FROM scan_results "
    "WHERE disc_type = 'bdmv' "
    "AND lower(file_path) LIKE '%.iso' "
    "AND ("
    "  audio_tracks_json IS NULL "
    "  OR audio_tracks_json = '[]' "
    "  OR audio_tracks_json LIKE '%\"language\":\"und\"%'"
    ")"
) as cur:
    rows = await cur.fetchall()
```

`disc_type = 'bdmv'` is the canonical value the scanner writes for both folder-BDMV and BD-ISO discs (`backend/scanner.py:165`). DVD ISOs are written with `disc_type = 'dvd'` and folder BDMVs lack the `.iso` suffix, so the two-condition selector cleanly bounds the sweep to BD ISOs only.

This pulls any BD ISO row with at least one und track or no tracks at all. False positives (rows with `[eng, und]`) are accepted at this stage — Python filtering handles those.

**Stage 2 — Python filter.** For each candidate, parse the JSON and keep only rows where `audio_tracks` is empty OR *every* track has `language == "und"`:

```python
audio = json.loads(row["audio_tracks_json"] or "[]")
if audio and any(t.get("language") != "und" for t in audio):
    continue  # partial coverage; out of scope per Q&A
```

### Action per row

For each row that passes both stages, the action mirrors `_backfill_disc_languages_v065` exactly:

```python
1. Skip if Path(file_path).exists() is False (stale; let normal removal handle).
2. probe = await probe_file(file_path)              # now routes through libbluray
3. If probe is None: continue.
4. raw_audio = probe.get("audio_tracks", [])
   raw_subs  = probe.get("subtitle_tracks", [])
5. native_lang = detect_native_language(raw_audio)
6. audio_tracks    = classify_audio_tracks(raw_audio, native_lang)
   subtitle_tracks = classify_subtitle_tracks(raw_subs, native_lang)
7. audio_json    = json.dumps([t.model_dump() for t in audio_tracks])
   subtitle_json = json.dumps([t.model_dump() for t in subtitle_tracks])
8. has_removable      = 1 if any(not t.keep for t in audio_tracks)    else 0
   has_removable_subs = 1 if any(not t.keep for t in subtitle_tracks) else 0
9. UPDATE scan_results SET
     audio_tracks_json = ?,
     subtitle_tracks_json = ?,
     native_language = ?,
     has_removable_tracks_flag = ?,
     has_removable_subs_flag = ?
   WHERE file_path = ?
```

If step 6's classified audio_tracks is STILL all-und (libbluray failed too), the UPDATE still fires — the row's other classified fields might still have improved (e.g. `keep` flags, `score`). The cost of writing an unchanged row is negligible.

### Idempotency

`settings.iso_lang_backfilled_v075` boolean flag, checked at method entry and set at method exit. The read is inlined (matching v0.6.5's pattern) rather than via a helper, since no `_get_setting` helper exists on the Watcher class — only `_set_setting`:

```python
flag_key = "iso_lang_backfilled_v075"
db = await aiosqlite.connect(self.db_path)
db.row_factory = aiosqlite.Row
try:
    async with db.execute(
        "SELECT value FROM settings WHERE key = ?", (flag_key,)
    ) as cur:
        row = await cur.fetchone()
    if row and row["value"] == "true":
        return  # already done
    # ... candidate pull happens on the same connection ...
finally:
    await db.close()
# ... per-row processing on fresh connections (matching v0.6.5) ...
await self._set_setting(flag_key, "true")
```

The flag is set even when zero candidates were found (so an empty sweep doesn't re-query every startup) and even when some per-row probes failed (so a single corrupt ISO doesn't keep the sweep retrying forever).

### Logging

Two lines per sweep, both `[WATCHER]` prefixed:

```
[WATCHER] v0.7.5 backfill: re-probing N BD ISO rows for language metadata
[WATCHER] v0.7.5 backfill: updated N rows
```

No per-row spam, no UI toast. Matches v0.6.5 / v0.6.7.

### Tests

Five unit tests in `backend/tests/test_watcher.py` (alongside any existing v0.6.5 tests; create the file if absent):

1. **Selector includes all-und BD ISO row** — fixture row with `disc_type='bdmv'`, `.iso` path, `audio_tracks_json='[{"language":"und"},{"language":"und"}]'` → picked up.
2. **Selector excludes partial-coverage row** — same fixture but `[{"language":"eng"},{"language":"und"}]` → skipped (Python stage filters out).
3. **Selector excludes DVD ISO + folder BD** — fixture row with `disc_type='dvd'` and `.iso` path → skipped; fixture row with `disc_type='bdmv'` and folder path (no .iso suffix) → skipped.
4. **Idempotency** — set the flag manually, run the method, assert zero DB reads of scan_results.
5. **End-to-end** — fixture row with `audio_tracks_json='[]'`, mocked `probe_file` returns the v0.7.4 libbluray result `{audio: [fre, eng], subtitle: [fre, fre]}`, run the method, assert the row's `audio_tracks_json` now carries the two classified tracks with correct languages.

### File changes

- `backend/watcher.py` — add `_backfill_iso_languages_v075` method (~80 lines), add call in `check_once()` (1 line).
- `backend/tests/test_watcher.py` — add 5 unit tests (~80 lines).

No new files. No schema migration. No frontend changes. No dependency changes.

## Risks & mitigations

- **Risk:** A BD ISO that libbluray genuinely can't parse (corrupt, exotic UDF, …) would have its row overwritten with another all-und classification.
  **Mitigation:** Accepted as no-op — the row's state is unchanged in user-visible terms. Idempotency flag still gets set so the sweep doesn't loop on this row across restarts.

- **Risk:** The libbluray ctypes path opens the BD ISO file directly, which can be slow on large network shares (Elephant on the user's NUC took ~150ms in verification).
  **Mitigation:** Sweep runs once per install, single-threaded, only on actual stale rows. For a library with even 100 BD ISOs, that's ~15s wall-time at install. Acceptable for a one-shot.

- **Risk:** A user with the flag already set (from a hypothetical earlier dev build) wouldn't get the backfill.
  **Mitigation:** The flag is namespaced `_v075` so future iterations would use new keys. Current flag will only be set by code shipped in v0.7.5+.

## Acceptance criteria

1. Fresh v0.7.5 install with no existing BD ISO rows → flag gets set in `settings`, log shows `re-probing 0 BD ISO rows`, no writes to `scan_results`.
2. v0.7.4 → v0.7.5 upgrade with existing all-und BD ISO row → row's `audio_tracks_json` updated to carry libbluray-derived languages on first watcher cycle. Log shows `updated 1 rows`.
3. v0.7.4 → v0.7.5 upgrade with existing partial-coverage BD ISO row (`[eng, und]`) → row unchanged. Log shows `updated 0 rows` (the row was pulled by SQL but filtered out by Python).
4. v0.7.4 → v0.7.5 upgrade with existing DVD ISO row → row unchanged. Log shows `updated 0 rows` (filtered at SQL stage).
5. Second watcher cycle after a successful sweep → method returns immediately, no SQL.
6. All 5 unit tests pass.
